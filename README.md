# ME102B automatic pill dispenser

Firmware for a single-canister automatic pill dispenser on the original
Adafruit HUZZAH32 (BOM product 3591), with a DC gearmotor, TFT, sensors and an
RTC. The `dispenser` environment contains the integrated firmware:

- It homes the drum and shows the clock and next dose.
- It dispenses on schedule (up to 3 times a day, stored in NVS) or on demand.
- Each dispense indexes one pocket at a time, up to `MECH_MAX_INDEX_STEPS`
  pockets, and stops at the first pocket that drops a pill.
- It verifies each pill with the beam-break and load cell, then reminds the
  user to take it.
- It handles jams, double drops and misses.

**None of it has been run on hardware yet.** The logic is checked by host
unit tests and a simulation. Component tests are uploaded one at a time and
replace the installed program.

## Build, test and upload

Install Python 3.11 and Git, then:

```sh
git clone https://github.com/ramonavila04/ME102B.git
cd ME102B
python -m venv .venv
# macOS/Linux:
source .venv/bin/activate
# Windows PowerShell instead: .venv\Scripts\Activate.ps1
pip install -r requirements-dev.txt

pio test -e native              # host unit tests + dispenser simulation (no board needed)
pio test -e native_small -e native_caplet -e native_cap0   # same suite per pill block in mechanism.h
PLATFORMIO_BUILD_FLAGS=-DMECH_PILL_SMALL pio run -e dispenser   # firmware for another pill (default: iron)
pio run                         # integrated dispenser firmware (default env)
pio run -e dispenser -e beam-break -e load-cell -e ui-panel -e motor-drv8833 -e motor-tb6612
pio run -e dispenser-wokwi      # simulated-motor build for Wokwi (never flash on the real dispenser)

pio device list
pio run -e dispenser -t upload --upload-port YOUR_PORT
pio device monitor -e dispenser --port YOUR_PORT
```

Use the same environment for building, uploading and monitoring. Close the
serial monitor before uploading. Linux ports usually look like `/dev/ttyUSB0`;
Windows ports like `COM3`. The PlatformIO VS Code extension can also open this
project. The first build downloads the pinned ESP32 platform, toolchain and
libraries: HX711 0.7.5, Adafruit ILI9341 1.6.1, GFX 1.11.11, BusIO 1.16.2 and
RTClib 2.1.4. CI (`.github/workflows/firmware.yml`) builds every environment
and runs `pio test -e native -v`.

### Dispenser serial commands (115200 baud)

| Command | Action |
| --- | --- |
| `d` | Dispense now |
| `a` | Acknowledge (same as Select) |
| `h` | Re-home |
| `s` | Status |
| `t` | Tare the empty cup |
| `c 10` | Calibrate with a 10 g mass |
| `T 2026-11-09 08:00:00` | Set the RTC |
| `D1 08:00`, `D2 off` | Set or clear dose times |

The UI uses the pot to scroll, Select to choose and Back to go back. The menu
offers: Dispense now, Dose 1 to 3 (in 15-minute steps), Set clock, Re-home and
Exit.

## Project layout

- `include/pins.h`: the single system pin map for the original HUZZAH32.
- `include/mechanism.h`: the mechanism contract (index angle, speed, ramps,
  jam and verification limits). It is generated by the mechanism simulator;
  the firmware only reads these names.
- `lib/dispenser_core`: hardware-independent logic. It contains the state
  machine, trapezoid profile and closed-loop move, stall detector, pill-count
  verification, schedule and pot-menu hysteresis.
- `firmware/dispenser`: the thin Arduino adapter (ISRs, PWM, HX711, RTC, NVS,
  TFT).
- `firmware/component-tests`: standalone beam, load-cell, motor and UI-panel
  programs.
- `test/`: Unity tests (`test_core`) and a full-system simulation
  (`test_sim`) for `pio test -e native`.
- `diagram.json`, `wokwi.toml`: Wokwi model of the `dispenser-wokwi` build.
- `docs/source-programs`: verbatim text extracted from the three supplied Word
  documents.
- [System wiring, power budget and bring-up](docs/wiring.md), with the
  generated [diagram](docs/wiring.svg) (`python3 tools/gen_wiring_svg.py`).
- [Hardware notes](docs/hardware.md): board and driver differences to check
  first.
- [Component test procedures](docs/component-tests.md): commands and pass
  criteria.
- [Team workflow](CONTRIBUTING.md): branches and pull requests.

The supplied motor and load-cell text was each missing its final closing
brace; the working copies repair those endings. The load-cell working copy
uses the pinned HX711 dependency.

## Scope and verification

Builds check compilation, not wiring or dispensing accuracy. The native tests
check the logic against a simulated motor and sensors, not the real
mechanism. The team must record hardware tests. The pin map changed when the
TFT, pot, RTC and buttons were added: STBY moved from 32 to 26, the status LED
moved from 13 to 12, and PWMA is now on GPIO21. Rewire bench setups before
uploading; see [wiring.md](docs/wiring.md#changes-from-the-previous-pinsh-and-why).

PlatformIO pins Arduino-ESP32 2.x through espressif32 6.9.0. The source motor
comments referred to 3.x, so this is a deliberate choice for a reproducible
toolchain, not a claim that it matches the original development environment.
